Beta fixes and hardening

These fixes stop answers being lost, the app showing the wrong state, and dead ends in the beta's core journey: onboarding, the daily session, leaving and resuming, finishing, and coming back later. Each fix was reproduced before it was changed, has a regression test, and was checked in a web build of the real app against a local API. None of it has been tested on a phone. Nothing was pushed, deployed or migrated.

How to apply. 1-beta-fixes-and-hardening.mbox is a git format-patch series on top of main at 1363407. Apply it with git am 1-beta-fixes-and-hardening.mbox.
  • It contains 11 commits: the approved UI polish (f24224d), the day-session fixes, the hardening fixes, a merge, and one commit that makes the two branches work together.
  • In total: 47 files, +1604/−145.
  • Recommended order: review, merge, run the checks below, then build for TestFlight or ship an OTA update on the beta channel.

What "verified" means here

  • Code and unit tests: every fix.
  • Browser: every fix was reproduced in the web build at 393×852 and 360×780, before and after. The integrated build was walked from onboarding to Day 1, leaving halfway with a draft, resuming and finishing. The rest of the integrated walk (next day, offline sync, Log out, a fresh sign-in) passed on the individual branches. The run on the merged build was cut short by a usage limit.
  • Device: none. There was no phone or simulator. See the device checks below.

Remaining beta blockers (ranked)

  1. Week-2 access for testers (owner and production database). The only way past week 2 is a hand-given beta_grant row (90 days; the admin button or scripts/grant-beta-all.sql, which covers only accounts that already exist). New testers and lapsed grants are stuck. Testers are on week 2 (Wuzhen). Check every tester, or grant automatically while BETA is on (an API change and a deploy). Also: wrangler.toml says the beta runs on the production backend, which contradicts docs/BETA-BACKEND.md.
  2. Ship it. It's unknown which commit TestFlight is running (Gate 0 in docs/BETA-GATES.md).
  3. Content drift. 75694f6 changed the app copy without regenerating seed-content.sql. Regenerate it (db:seed:gen) and reseed after deploying the API. The copy is still marked as needing native review.
  4. Server pacing (product decision plus an API deploy). Completion is stamped when the answers arrive, so a day finished offline late at night costs her the next day. Proposed: base assertDayOpen on her claimed local date (completedOn).
  5. Day screen (handled by the session redesign):
    • Reopening yesterday's day says «Listo por hoy / Mañana…».
    • «Ver lo que respondiste» opens the completion card, not her answers.
    • Day 1 opened from onboarding may skip the week-1 opening with its safety note (seen once).
  6. /api/me returning 5xx at sign-in lands her on the welcome screen and polls about twice a second. Not fixed; work had started but is unfinished and not in the patch.
  7. The offline banner covers the top controls (taps still work). Needs design.
  8. Owner decisions:
    • expired-session copy;
    • Log out keeping unsent answers;
    • a link from Hoy back to week 1 (the route exists via Atlas → «Ver lista»);
    • legal URLs (Gate 1).
  9. Círculos: «Mis círculos» stays on «Cargando…» after she picks interests without joining a circle.

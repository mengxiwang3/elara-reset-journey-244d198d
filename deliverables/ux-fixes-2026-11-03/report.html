02 · Short answers and the closing reply

Prompt (stepReply.ts): a new readingRule(position, total) is used by both prompt paths, the old one (days without a purpose, e.g. W4D4) and V2. - Every step: a short answer is a real answer (e.g. “todo bien”); acknowledge it plainly. - Mid-day: a retry may be invited only for off-topic answers, greetings, tests, or words that don’t answer the question. - Last step: acknowledge in one sentence without interpreting, close, never ask for another answer or invite a retry, and don’t ask a question. This removes the old contradiction. V2’s “narrow it” becomes “take it as it is”. - Nothing was added to NON_ANSWER_PHRASES, and nothing is rejected for being short.

Quotes: sanitize → unwrapQuotes. Quotes are stripped only when a matching pair (“…”, “…”, «…», ‘…’, ‘…’) wraps the whole reply and no other quote mark is inside it.

Tests (API): - Prompt assertions for both paths: last step, mid-day, and a one-step day. - Through the real route, «Todo bien» on the last step of both day types reaches the model with retry falsy. - sanitize: embedded quotes are kept; balanced outer «», “” and “” are stripped; unquoted text and a single unmatched quote are left as they are.

Not visible in screenshots: the local API has no model, so the authored line shows.

03 · Pregunta keyboard: traced, no change

Path traced - app/(tabs)/ask.tsx renders ScreenShell, then the shared KeyboardAvoider (not the toScreenBottom variant). - KeyboardAvoider passes measureInWindow as the keyboardVerticalOffset to React Native’s KeyboardAvoidingView (padding). - KeyboardAvoidingView (RN 0.86) listens to keyboardWillShow on iOS and keyboardDidShow on Android, and animates the padding with LayoutAnimation. - useKeyboard() changes the composer’s bottom inset in a separate render. - 50 ms after the keyboard opens, scrollToEnd runs (ask.tsx:178–184). - BandDay and the step screen’s two-pass reveal are not on this path.

Hypothesis: - iOS: the composer rises with the keyboard, while the last bubble returns only with the delayed scrollToEnd. - Android: everything waits for keyboardDidShow, so the composer is briefly covered, then jumps.

No defect was shown without a device; the shared components are untouched.

05 · Saving phrases

Answers are still saved in the day’s history automatically. What changed is how a phrase gets into «Frases que guardaste».

Change - Flag: saved?: number | false on the answer record, with isSavedPhrase and savedAfterEdit. The server (saveStep) and the phone (progressAfterAnswer) record saved: false on every new keep answer, which stops the automatic promotion. Editing saved words keeps them saved. - Endpoint: PUT /api/me/paths/:area/days/:day/steps/:stepId/saved sets only that flag (json_set). It returns 400 for a step that keeps nothing and 404 when there is no answer. - Phone: setPhraseSaved updates at once, rolls back if the server fails, then refreshes. - Completion screen (also on a reopened day): - her phrase verbatim, with its question or task; - one control, «Guardar esta frase» ↔︎ «Guardada en tus frases» (tap again to remove); - repeat taps are ignored; - a failure line if saving fails; - hidden while Elara’s reply is pending. - Shelf: collection.ts shows only saved phrases. - Hoy: TakeawayRow puts the question or task above her verbatim words. Nothing is filtered by length, so «Todo bien» shows with its question.

Existing users: phrases promoted automatically before this change stay saved, because an absent flag reads as saved. There is no migration, and she can remove any of them with the same control. This is reversible later with a one-off migration.
